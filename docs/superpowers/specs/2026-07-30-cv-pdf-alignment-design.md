# CV page: replace content and align design with the print PDF

**Date:** 2026-07-30
**Status:** Approved, pending implementation
**Scope:** `/cv` and `/de-de/cv` only

## Problem

The `/cv` page carries an older CV: a "Fractional CTO, Self-Employed, Jun 2023 – Present"
employment history, no company name, and a flat highlight list with no tech attribution.

A newer CV exists as a pair of print PDFs, generated by
`~/Documents/applications/lucid-labs/source/build.mjs`. That script holds both the
current content (DE and EN) and the CSS that produced the PDFs, so it is the single
source for this work.

The PDFs also use a different visual language than the site. The site renders experience
as a dot-and-stem timeline and everything else as a "bento" grid of bordered cards. The
PDF uses one rhythm throughout: a narrow mono column carrying date and location on the
left, content on the right, under section labels whose rule flexes off to the right.

## Goal

1. Replace the `/cv` content with the data in `build.mjs`, both locales.
2. Rebuild the page in the PDF's layout language, at web scale.

## Decisions

Settled with the user before design:

| Question | Decision |
|---|---|
| How literally to match the PDF | Adopt its **structure** at web scale. Keep dark/light mode, reveal animations, and responsive collapse. Not a fixed-A4 paper replica. |
| "Current Training & Focus" list | **Drop.** `build.mjs` defines the data but its `render()` never emits it, so it appears in neither PDF. |
| Homepage strings that now disagree | **Out of scope.** Report them after implementation; the user decides separately. |

## Content source

All copy comes from `build.mjs` verbatim — the `de` object (lines 7–162) and the `en`
object (lines 164–306). No invented facts, no paraphrasing.

Two shape notes that the current type does not allow:

- The `Jun 2023 – Mar 2025` sabbatical entry has **no** `company` and **no** `highlights`.
- `earlierExperience` entries have **no** `location`.

`en` spreads `de`, so `communityActivitiesLabel` is `Mentoring & Talks` in **both**
locales. Both PDFs confirm this; it is intentional, not a missing translation.

## Data model

### Highlights

PDF highlights carry inline formatting as raw HTML:

```
<strong>Mobile app for Pool Position GmbH</strong> (Apr 2026 – present): porting core
web app features to mobile <span class="tech">TypeScript · React Native · AWS</span>
```

Locale files hold typed strings, not markup (`AGENTS.md`: "Components accept typed string
props"). Model the parts instead:

```ts
interface CvLink {
  label: string;
  href: string;
}

interface CvHighlight {
  lead: string;                 // rendered bold
  leadLink?: CvLink;            // link inside the bold lead, in parentheses
  leadNote?: string;            // plain (non-bold) parenthetical after the lead
  omitColon?: boolean;          // suppress the colon; a few entries read as one sentence
  text: string;                 // body copy
  link?: CvLink;                // trailing link in the body
  tech?: string[];              // mono run, joined with " · "
}
```

Render order: **`lead`** ` (leadLink)` ` (leadNote)` `:` ` text` ` link` ` tech` — with
`leadLink` inside the bold run and `leadNote` outside it, matching the PDF.

This covers all four highlight forms in the source data:

| Source form | Fields used |
|---|---|
| `<strong>lead:</strong> text <span class="tech">…</span>` | `lead`, `text`, `tech` |
| `<strong>lead</strong> (Apr 2026 – present): text <span class="tech">…</span>` | `lead`, `leadNote`, `text`, `tech` |
| `<strong>Job Directory (<a>www.job-directory.eu</a>):</strong> text` | `lead`, `leadLink`, `text`, `tech` |
| `<strong>lead</strong> and coordination with…` (no colon) | `lead`, `omitColon`, `text` |

The component renders the colon, parentheses and middot separators, so no locale string
contains punctuation-as-markup.

The last two forms were missed in the first draft of this spec and found while writing the
implementation plan. `leadNote` is distinct from `leadLink` because the PDF renders the
date parenthetical in plain weight but the Job Directory URL in bold. `omitColon` exists
because EN `Client relationship management` and DE `Kundenbetreuung` genuinely differ:
the German entry takes a colon, the English one does not.

## Layout

### Header

The PDF leads with a mono eyebrow, then the name as the display heading, then address and
contact in mono. The site currently makes "Curriculum Vitae" the display heading and hides
the name in a print-only block.

Align with the PDF: `cv.headline` becomes the mono eyebrow, `cv.identity.name` becomes the
visible `<h1>`. The download button keeps its current position.

### The row primitive

Every section below the summary is the same two-column grid:

```
lg:  grid-cols-[180px_1fr]   gap-x-10
md:  grid-cols-[140px_1fr]   gap-x-8
<md: grid-cols-1             side column runs above content, horizontally
```

The left column is mono, small, `text-foreground` for the period and `text-text-faint`
for the location beneath it. This replaces both the timeline's aside+marker columns and
the bento cells' internal label.

### Section order

Matching the PDF exactly:

1. Header — eyebrow, name, address, contact
2. Summary — `border-top`, larger body size
3. Experience
4. Earlier Positions
5. Skills & Expertise — skill groups, then Languages, then Soft Skills, all as labelled
   rows under **one** section label
6. Education
7. Certifications
8. Community & Volunteering — roles, then the Mentoring & Talks row
9. Hobbies & Interests

Languages and Soft Skills get no section label of their own; they are rows inside Skills
& Expertise. This is what the PDF does and it is easy to get wrong.

### Marks

- **Section label** — mono, uppercase, `tracking-[0.12em]`, muted, with `flex-1` rule after
- **Role** — display font, regular weight
- **Company** — mono, uppercase, `tracking-[0.14em]`, **accent**
- **Highlight bullet** — accent block `5px × 2px`, not a disc
- **Tech run** — mono, smaller, muted, middot-joined
- **Tag chip** — `1px` border, mono, `white-space: nowrap`
- **Language** — display name over mono uppercase level
- **Soft skills / interests** — plain middot-separated list

Removed: timeline dot, timeline stem, bento cards, card padding, `rounded-sm` on chips
(the PDF's tags are square).

### Colour

Existing `--v8-*` tokens throughout. The PDF's `--accent: #B82A00` is already the site's
light accent, so light mode matches the PDF exactly and dark mode uses `#FF3B00`.

## Components

`cv-section.tsx` is 378 lines and this change adds structure to it. Split into
`src/components/cv/`:

| File | Responsibility |
|---|---|
| `cv-section.tsx` | Composition; owns section labels and ordering |
| `cv-row.tsx` | The two-column primitive: `side` and `children` |
| `cv-experience-entry.tsx` | Role, company, description, highlight list |
| `cv-highlight.tsx` | One `CvHighlight` → bold lead, links, body, tech run |
| `cv-tags.tsx` | Bordered chip list |

All static TSX, no hydration — matching the current component. The download button's
handler stays in the page `<script>`, since a React `onClick` would be dropped from the
emitted HTML.

## Print stylesheet

`src/styles/cv-print.css` (230 lines) is written against `.bento-*`, `.cv-entry__dot` and
`.cv-entry__stem`, none of which survive. It needs rewriting, but shrinks: the screen
layout now *is* the print layout, so it no longer has to restructure anything.

What it keeps:

- Light palette override (print is always light)
- Print type scale — roughly the PDF's 9.8px body
- `@page { size: A4; margin: 11.5mm 16mm; }`
- `break-inside: avoid` on rows
- Page break before Skills & Expertise
- Hiding nav, footer, theme toggle, download button, and reveal transforms

## Cleanup

Remove `.bento-grid` and the nine `.bento-area--*` rules from `src/styles/global.css`
(lines 210–271). Nothing else references them once the component is replaced.

## Out of scope

The new CV contradicts homepage copy that this change does not touch. After
implementation, report — do not fix:

- The hero implies continuous self-employment since Jun 2023; the CV now splits that into
  a sabbatical through Mar 2025 and consulting from Apr 2025.
- `src/content/authors/sebastian-heitmann.json` has no company name.
- The CV's summary wording has diverged from the homepage pitch.
